# ADR-006: Estrategia de Internacionalización (i18n)

## Estado
Aceptado

## Contexto
El sistema debe ser accesible en español e inglés (RF-12). Esto afecta tanto a los literales de la interfaz (Frontend) como a ciertos mensajes de error de la API (Backend).

## Decisión
Se adopta un enfoque de **i18n en ambos extremos**:
1. **Frontend:** Uso de la librería `react-i18next`. Los textos se almacenan en archivos JSON independientes (`public/locales/{lang}/translation.json`). El idioma se detecta por el navegador o selección manual.
2. **Backend:** Los mensajes de error y validaciones se enviarán mediante códigos de error estandarizados, permitiendo que el frontend decida la traducción, o usando el header `Accept-Language` en FastAPI para localizar mensajes dinámicos.

## Consecuencias
- **Positivas:** Separación clara entre lógica y contenido. Añadir un tercer idioma es tan simple como añadir un nuevo archivo JSON.
- **Negativas:** Requiere disciplina en el desarrollo para no escribir "hardcoded text" (texto plano) en los componentes.
